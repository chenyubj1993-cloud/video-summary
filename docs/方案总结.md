# 方案总结：把一集长课程变成一份能读的讲义

> 这份文档记录「为什么这么做」和「依据是什么」，不是使用说明。用法见 `README.md`。
> 所有数字都来自实测（视频 BV1E9U8BBEvZ，《多模态视觉大模型》40 分P / 6.92 小时）。

---

## 1. 问题

长课程的问题不是"没有摘要"，是**摘要没法当书读**：

- 拿到的是一段 500 字概述，想查"MoCo 的动量系数取多少"还得回视频里翻；
- 讲到"如图"的地方，摘要里没有图，也没有那一秒在哪；
- 讲者前后说法不一致（第 5 集说 4096，第 9 集说 4097），摘要会照抄一个、丢掉另一个；
- 想复习时，没有章节、没有索引、没有自测。

所以目标不是"压缩"，是**重建一份有出处的书**：能按章读、能查具体数字、能点回原片核对、能自我检查。

这个目标决定了整条链路必须**先解决"文本可信"，再解决"写得好看"**——于是有了下面这条看起来比"调个 API 出摘要"重得多的流水线。

---

## 2. 为什么彻底不用平台字幕

这是整条链路最反直觉的一个决定。B 站有 AI 字幕，白拿的文本不要，反而本地跑 13 分钟 ASR——因为抽样实测发现平台字幕是坏的。

抽了两个站内 40 分P 课程（共 80 个分P）：

| 现象 | 实例 |
|---|---|
| 字幕与视频内容无关 | 讲多模态大模型的课，字幕是英雄联盟解说：「先来看这个 VN 1 级学 Q 打出真伤」 |
| 一本正经地串台 | 讲强化学习的课：电视剧台词、行车 vlog、英文歌词轮流出现 |
| 多个分P 字幕完全相同 | P27 与 P32 都是 278 条 / 2261 字；P21 与 P26 都是 590 条 / 7463 字 |
| 覆盖率离谱 | 有的分P 869%（比音频还长），有的 8% |
| 40 个分P 里 39 个"有字幕" | 但真正能用的不到一半 |

决定性验证：下载 P1 音频转写，得到的是课程真实内容（「我们的课程会涉及视觉大模型的绝大多数内容…」），而平台给那一集的字幕是英雄联盟。**音频是对的，字幕是错的。**

结论：平台字幕只能当"有没有"的信号，不能当文本来源。本地 ASR 花 13 分钟，换来的是可控。

## 3. 链路

```
           ┌─ 字幕？✗ 不用（见第 2 节）
音频 ──────┤
           └─ 本地 ASR（faster-whisper turbo）→ 逐句时间轴
                                   │
                        词表纠错（307 处）→ 已纠错转写 + 逐条改动记录
                                   │
                    ┌──────────────┼──────────────┬─────────────┐
                逐集摘要        数值矛盾         抽帧 + OCR      概念断言
                    │              │                 │              │
                总览.md      consistency.md      板书.md / 图     claims
                    └──────────────┴─────────────────┴──────────────┘
                                   │
                        分章写正文（教材体，逐句带出处）
                                   │
                     术语注解 → 自测题 → 配图 → 名词速查 → 前置体检
                                   │
                          拼讲义（HTML/MD + 6 附录）
                                   │
                              gate 六项体检
                                   │
                      讲义.html / 精简版.html / PDF
```

| 层 | 做什么 | 用模型 | 产物 |
|---|---|---|---|
| L0 转写 | 下载 + GPU 转写 + 断句 | 本地 whisper | `segments.json`、40 组 txt/srt |
| L1 纠错 | 词表 + 搭配约束替换 | 否（纯规则） | `segments_fixed.json`、`changes.md` |
| L2 结构 | 章节切分、逐句写着 | 是 | `handout/ch*.md` |
| L3 增强 | 注解、题、图、速查、前置体检 | 部分是 | 附录 B/E/F、`prereq.md` |
| L4 体检 | 六项硬检查 | 否 | `gate` 退出码 |
| L5 交付 | 拼讲义、精简版、PDF | 是（精简版） | `讲义.*`、`精简版.*` |

## 4. 关键决策与依据

### 4.1 转写：本地 GPU，28–32x 实时

同一段 300 秒音频上的对照：

| 配置 | 速度 | 质量抽检（"预训练"这个词） |
|---|---|---|
| CPU small int8 | 3.5x | 错成「预讯链」 |
| CPU medium int8 | 1.1x | 错成「预训链」 |
| GPU small fp16 | 14.9x | 同上 |
| GPU medium fp16 | 13.0x | 同上 |
| **GPU large-v3-turbo fp16** | **28.9x** | **正确** |

turbo 又快又准，所以默认它。整集 6.92 小时 → 12.9 分钟（32.3x），156,612 字 / 10,800 句。

两个实现坑：

- **av 19 与 faster-whisper 1.2.1 不兼容**（`av.open(..., metadata_errors=...)` 参数不存在），降级 av 又没有 cp312 wheel → 改成自己用 `av.AudioResampler` 解码成 16k 单声道 float32，绕开它的 `decode_audio`。
- **CUDA DLL**：本机只装了驱动（592.01 / CUDA 13.1），没有 Toolkit。装 `nvidia-cublas-cu12` + `nvidia-cudnn-cu12` 后，必须把 `<site-packages>\nvidia\{cublas,cudnn,cuda_nvrtc}\bin` **加到 `PATH` 前缀**（只 `os.add_dll_directory` 不够），且要在 `import ctranslate2` 之前。

### 4.2 纠错：词表 + 搭配，不靠置信度

**先证伪了一个想当然的方案。** 原计划用 `avg_logprob < -0.6` 找可疑句再让模型复核。实测 10,800 句里最小只有 **-0.266，没有一句低于 -0.6**——VAD 已经把噪声音频切干净，剩下的句子模型都很自信，而"自信"和"正确"是两件事。这条路是空转的。

实际有效的是词表 + 搭配约束：47 条 `obs` 规则命中 **307 处**。

词表的三条硬规矩（`glossary/README.md`）：

1. **只存误听形**（`DINO ← Deno`），不存正确写法。反过来做会把对的字改错。
2. **合法词不进表**。`论文` 本身合法，只有前面是「下游 / 前置」时才替换——不加约束会把全篇的"论文"改掉。
3. `hyp` 只统计命中次数、不动文本。确认后才升 `obs`。

错误画像说明了为什么必须这么做：`任务` 全片正确 149 次、错 13 次（`论物`/`论武`/`论文`），错误全部集中在「下游 / 前置 + 任务」这个搭配上——不是口音导致的稳定映射，是解码器的词频偏置。所以搭配约束比"整词替换"精确得多。

**治不了的**：字符层合法的知识型错听。`智源研究院` 被听成「清华河资源研究院」——读音接近、字全合法、字符串表无解，只能人读。这类只能在讲义里标进「存疑与勘误」。

### 4.3 章节：按内容切，不按录音切

第一版的章节边界等于分P 边界（1 / 5 / 7 / 7 / 7 / 7 / 6），于是最难的第三章（要讲 ViT、MoCoV3、DINO、MAE、SAM 五个模型）反而是全书第二薄的，密度只有 31 字/音频分钟——比摘要还薄。

两处改动：

- **切分**：按分P 标题的数字前缀聚类（`## 3.1 ViT…` 归章 3），识别不到再退回"每 6P 一章"。分P 标题本身就是人工大纲，比让模型聚类可靠。
- **写法**：从"讲了什么"改成教材体的四段式——**为什么需要它 / 它是怎么做的 / 设计上的取舍 / 代码**。第三段是关键：讲者讲过的动机（DINO 为什么去负样本、MAE 为什么 mask 75%）在旧版里全丢了；材料没讲的地方明确写「材料未展开」，不许模型补课。

结果：16,028 → 35,844 汉字，密度 39 → **86 字/音频分钟**（教材区间 60–100，讲稿 200–300），出处从 762 涨到 942。

### 4.4 出处：每条论断都能跳回去

这是"和普通 AI 摘要"最大的区别，也是唯一能对抗幻觉的机制：

- 生成时强制每句带 `[Pxx mm:ss]`，时间码只能从素材里抄；
- 拼装时 `cite.verify` 逐条回查 `segments`：分P 是否存在、时间码是否在该P 时长内、那一秒 ±15 秒内有没有转写句子；
- 查不到的不删，标红——删掉等于替读者做了判断；
- HTML 里渲染成深链，点开直接跳到视频那一秒。

实测 931 处全部核对到原文（100%）。

### 4.5 数值矛盾与概念矛盾：只标注，不替讲者改口

- `consistency`：只比较**同一个分P、180 秒内、同一属性**的两次说法，且判定相似要满足"差一是大数"「差 10 的整数倍」「像是多打一位」这类具体形状。全片报 3 组，全对（端口 2400/24000、`64×4096`/`64×4097`、1512/512）。宁可少报，不乱报。
- `claims`：句式版把 2,503 条原始断言过滤到 260 条、0 组矛盾——中文没有词边界，主体很容易抓成上半句的尾巴，所以它被定位成"宁可少报"的兜底。`--llm` 版走"抽断言 → 两步判定（是不是同一属性 / 能不能同时成立）→ 同一主体折叠"，最后报 9 组，逐条看约 6 组是真不一致。

原则：**发现矛盾就写进附录 D，不替讲者选一个"正确的"**。因为讲者自己可能前后改口，判断权应该在读者。

### 4.6 视觉通道：只做"念不出来的东西"

PPT 的公式、代码、架构图，口播往往只说"如图"。抽帧 + OCR 补这一块，几个实测结论：

- **必须 720p**。480p 下代码糊成 `otch_31z=64`；720p 能读到 `queue=torch.randn(C,K)`、`optimizer=optim.Adam(f_q.parameters(), lr=0.001)`。
- **阈值不能拍脑袋**。帧差实测 p50=0.00、p99=1.08、最大 6.7，翻页才 3–7。设 6 只能抓到个位数帧，设 **2.5** 正常。
- **过滤不能按词频**。静止的代码块每帧都一样，按"出现频率高就是界面"过滤会把内容一起删掉。按**几何位置**过滤才对（左 8% 工程树、上 2.5% 菜单栏、下 4% 状态栏）。
- **图必须锚到出处**：同分P ±30 秒内找不到 `[Pxx mm:ss]` 的帧不插——宁可少，不要乱放。

结果：543 帧 → 15 张图进正文，60 条 OCR 记录进附录 E。附录 E 直接从 `板书.md`（可读文本）生成，不依赖原始帧，所以中间帧可以删。

### 4.7 体检（gate）：六项，四项是硬指标

「讲得好不好」没法自动判，「有没有硬伤」可以：

| 检查 | 门槛 | 为什么 |
|---|---|---|
| 章节齐全 | ≥3 章，每章有「学习目标」「存疑与勘误」 | 骨架缺了，读起来就不是书 |
| 出处可核对 | ≥98% 时间码能落到真实句段 | 这是可信度的底线 |
| 术语干净 | obs 规则误听形残留 = 0 | 改错的字留在讲义里比漏改更糟 |
| 前置顺序 | 出现 ≥10 次却无定义 = 0 | 决定"能不能当教材读" |
| 覆盖率（参考） | ≥35 汉字/音频分钟 | **防"少写少错"**：只查准确性时，把讲义写空反而全对 |
| 前后一致（参考） | 数值冲突组数，只报不判 | 冲突多半是讲者口误，不是讲义错 |

覆盖率这条是这套评测里唯一的方向性指标——没有它，其他五项都在奖励"少写"。

### 4.8 精简版：重组，不是压缩

`brief` 不复用讲义正文，而是重新组织：一页地图 + 十条总纲 + 每章六块（这一章在回答 / 核心结论 / 概念关系 / 关键数字 / 代码要点 / 易错点）。

28,043 → 约 4,500 汉字（16%），阅读时间 1.7 小时 → **15 分钟**，236 处出处全部保留。取舍是：丢掉图的视觉冲击、丢掉逐段推导，保住"骨架 + 可查数字 + 能跳回原文"。

### 4.9 通用化：从"这一个课程"到"任意一个链接"

第一版是围绕那门 40 分P 课程长出来的，通用化时暴露了五处硬编码，逐个拆掉：

| 原来 | 现在 | 为什么这么改 |
|---|---|---|
| 只收 BV 号，链接要自己抠 | `source.parse()` 认 BV / bv / av / 网页链接 / m 站 / b23.tv 短链 / 带标题的分享文本；`?p=N` 自动转成 `--parts N` | 用户手上拿到的一定是链接，不是干净的号 |
| `cli.py` 里 21 条命令各自解析 | `main()` 里先把 argv 规整一遍 | 一处改动，所有命令都受益 |
| 分章靠分P 标题的数字前缀 | 有编号按编号；没有就按音频时间切（目标 25 分钟/章） | 单集视频、纪录片、直播回放没有"分P 标题"这种东西 |
| 提示词写死"技术课程编辑"，封面写"课程讲义" | `--style auto`：标题出现教程/精讲/考研等走教科书式，否则走笔记式（这一段讲了什么 / 关键信息 / 值得留意的说法） | 时政吐槽用"为什么需要它 / 设计上的取舍"套，会写得很假 |
| gate 固定要 ≥3 章、35 字/分钟 | 按分钟数定章节数（19 分钟要 1 章、70 分钟要 2 章、6 小时要 3 章），覆盖率门槛按风格取 18 / 35 | 短片硬凑三章只会注水 |

领域分类器没有升级成通用的——它靠关键词投票，把 19 分钟时政视频判成"美食与生活 1.29 / 编程 1.16"（置信比 1.11）。所以**风格判定改成标题优先**，领域只在标题没信号时才参考，且要求置信比 ≥1.25；领域置信不足时讲义封面干脆不显示领域。

实测三集不同形态：

| 视频 | 形态 | 结果 |
|---|---|---|
| BV1E9U8BBEvZ | 40 分P / 6.92h 课程 | 7 章 37,013 字、931 处出处、12 图 28 题，gate 6/6 |
| BV1xzy2zMExY | 单集 / 19 分钟时政吐槽 | 自动判为笔记式，1 章 2,226 字、46 处出处，gate 6/6 |
| BV1T917zFEwb | 单集 / 70 分钟考研带背 | 按时间切成 3 章、182 处出处，gate 6/6 |

**不支持的源要说清楚**：番剧/会员专享会被 yt-dlp 重定向到 bangumi，普通音轨拿不到；这类失败现在会直接说明原因，并给"手动放音频 + `--no-dl`"的退路，而不是抛一个 subprocess 栈。

### 4.10 跨期整合：把 N 期当一门课

单期工具满地都是，跨期没人做。`series` 做三件已存在工具的盲区：

1. **课程地图**：每期解决什么问题、依赖哪一期——不是把 N 份摘要叠起来，而是先按顺序排因果；
2. **重复讲过的概念**：`concept_key()` 归一化后跨期比对，标出"第 12 期讲过的，第 37 期又讲一遍"；
3. **跨期不一致**：同一主体（模型/参数/数字）在两期给了不同值，只列出来让人回去听，不替讲者裁决。

实现走的是 UP 主合集接口（不需要 wbi 签名）：`seasons_series_list` 拿 `season_id`，
`seasons_archives_list` 拿该合集下的 `bvid/title/duration`；已在某一集页面时，
`view` 接口的 `data.ugc_season` 就能反查出它属于哪个合集。

实测 3 期（各只取 P1）：地图 3 节、重复概念 1 个（Transformer 在 E02 与 E03 都讲了）、跨期数值冲突 0 组。
局限：只比"同一主体"的两个值，换措辞的说法抓不到；只读 P1 时结论也只覆盖 P1。

### 4.11 增量：改一章不重跑全书

每章算一个内容签名（分P 范围 + 转写文字的 md5），写进 `chapters_state.json`。
签名没变就跳过；`--force` 全量。这一条是为了"手改一章之后不想再看模型把别的章重写一遍"。

踩过的坑：第一版在"按 mtime 跳过"时不记签名，结果 `touch` 一下转写文件就触发全量重写
（而且用的是默认密度，把 7 章一起改成了更短的版本）。现在**跳过时也记录签名**。

### 4.12 自测：18 个纯逻辑用例

输入解析、分章切分、签名、出处解析、掩码、检索排序、门槛判定——这些是最容易改坏、
又最难靠看输出发现的地方。`tests/test_core.py` 用 unittest 覆盖它们，`python cli.py test`
几毫秒跑完，不需要网络、GPU、key。

写测试时反被测试纠正了两处：`cite.parse()` 的第三个元素是原文匹配串（不是页码），
`ask.BM25` 接收的是已分词列表（不是原字符串）——文档里没写清，测试逼着写清了。

## 6. 踩坑清单（按代价排序）

| 现象 | 原因 | 解法 |
|---|---|---|
| 模型读不出 `/`、`rn` | 480p 下代码区太小 | 强制 720p |
| 只抓到个位数帧 | 帧差阈值照静态画面直觉设成 6 | 实测分布后取 2.5 |
| 附录里全是 IDE 菜单栏 | 按词频过滤把静止代码当装饰删了 | 改按几何位置过滤 |
| 讲义里出现 `预训练（…（…））` | 注解被下一次采集当成"定义"再注入 | 采集前先收回旧注解 + 长词优先 + 区间互斥 |
| 术语被切坏：`残差（…）网络` | 短词匹配到长词前缀 | 命中后紧跟汉字且能续成更长别名就跳过 |
| 大模型给的列表/表格不换行，Markdown 拼成一段 | 模型输出习惯 | 渲染前 `normalize`：块级行前补空行 |
| 分章重复标题 `第 1 章 第 1 章 …` | 模型把章名抄进标题 | 去重 + 括号注解截断 |

## 7. 已知局限

1. **讲义正文是模型写的**。gate 保证"有出处、数字不打架、术语说清楚"，不保证"讲得对、讲得好"。抽样仍发现个别段落把上下文综合当成了原文（不带队时间码的句子 `cite` 查不到）。
2. **覆盖率 60 字/分钟在教材区间下沿**。按 `--density 200` 重跑 ch2–ch7 可到 100+，成本约 40 万 tokens；没做，因为边际收益要人读才知道。
3. **中文同音错听与纯数字错听说不了**（`拉玛 → LLaMA`、`718 → 768`）。试过两条路都否掉：数字"长得像"会把"196 维拼成 197 维"这种正确表述判错；借一致性冲突反推又常常找不到可比的一对。
4. **一致性检测只看得见"挨着属性词的数字"**。相隔几十分钟的口误、纯概念矛盾会漏。
5. **概念矛盾判定精度约 60%**（9 组里约 6 组真）。失败模式是"同一实体不同侧面"被当成矛盾。
6. **只在一台 Windows + 单卡上验证过**。代码里没有 Windows 专属逻辑，但没在 Linux 跑过。
7. **领域分类器是给 AI 内容调的**，非技术视频上不可靠（时政视频被判成"美食与生活"）。因此它只影响"加载哪张纠错词表"和封面上的领域标签，风格判定已改成标题优先。
8. **番剧/会员专享/需登录的源不支持**。会被重定向到 bangumi，普通音轨拿不到。

## 8. 如果继续做

按"性价比 / 差异化"排序：

1. **OCR × 口播交叉校验**（零模型成本）：屏幕上写 4097 而口播说 4096，两边都记了时间和文本，这是最高置信度的勘误来源。规则是"冲突时先怀疑 OCR"。
2. **提高正文密度**：`--density 200` 重写，把 60 → 100 字/分钟。
3. **问答层**：BM25 + 时间码深链，不需要向量库。用户问"MoCo 的动量系数是多少"，直接给出那句话和那一秒。
4. **跨系列整合**（设计稿在 `docs/plan-series-course.md`）：把同一 UP 主的 50 期当一门课来备——去重、看概念如何演化、抓自我修正。现有工具全停在"单期"。
